# whois_advanced v1.1

Консольный инструмент для обогащения списка IP-адресов данными внешних API и создания Excel-отчёта. Получает организацию, страну, город, регион, ASN, провайдера, почтовый индекс и часовой пояс, если источник их предоставляет.

Это данные геолокационных API, а не прямые WHOIS/RDAP-запросы. `netname` и `asn_description` остаются `N/A`: прежняя версия генерировала эти значения из названия организации, что не подтверждает реальные регистрационные данные.

## Установка

Нужен Python 3.10+ и доступ к PyPI. Проверено на Python 3.12. Для запросов нужны HTTPS-домены `ipapi.co` и `ipwhois.app`; API-ключи текущей реализации не нужны. Доступность и лимиты бесплатных API зависят от провайдеров.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

В Windows используйте `.venv\Scripts\python.exe` вместо `.venv/bin/python`.

## Пользовательский путь

1. Подготовьте UTF-8-файл с одним IPv4 или IPv6 на строку.
2. Запустите команду ниже.
3. Откройте полученный Excel-отчёт; ошибки указаны в консоли и колонках отчёта.

```text
# Пример содержимого входного файла
8.8.8.8
1.1.1.1 # комментарий после адреса
2606:4700:4700::1111
```

```bash
.venv/bin/python main.py --input ip_list.txt
.venv/bin/python main.py --input /path/to/ips.txt --output /path/to/report.xlsx
.venv/bin/python main.py --help
.venv/bin/python main.py --version
```

При запуске без параметров используется `ip_list.txt` рядом со скриптом. Новый отчёт создаётся рядом со скриптом с уникальной UTC-меткой времени в имени. Явно указанные относительные пути отсчитываются от текущей директории.

Неверные адреса пропускаются с указанием номера строки. Дубликаты удаляются после нормализации IPv6, порядок первого появления сохраняется. Комментарии `#` и пустые строки игнорируются. Локальные, служебные и зарезервированные адреса попадают в отчёт со статусом `skipped`, запросы для них не отправляются. Scoped IPv6 (`%interface`) не поддерживаются.

## Параметры

| Параметр | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `--input` | `ip_list.txt` рядом со скриптом | Входной UTF-8-файл |
| `--output` | `WHOIS_Analysis_Report_<UTC>.xlsx` | Путь к отчёту |
| `--overwrite` | выключен | Разрешить замену существующего отчёта |
| `--timeout` | `10` | Таймаут соединения/чтения, секунды; это не общий лимит времени запуска |
| `--delay` | `1` | Пауза между адресами, секунды |
| `--retries` | `2` | Число повторов для каждого API после первой попытки |

Основной источник — `ipapi.co`, резервный — `ipwhois.app`. Повторы выполняются для таймаутов, ошибок соединения, HTTP 429 и HTTP 500/502/503/504. Между попытками — 1, 2, … секунд с пределом 60 секунд. Числовой `Retry-After` учитывается с тем же пределом. Постоянные HTTP-ошибки, некорректный JSON и ошибки API приводят к переходу к резервному источнику.

## Excel-отчёт

Всегда создаются шесть листов, включая пустые:

- «Все IP-адреса»: сведения об адресах, источник и диагностика.
- «По организациям»: число адресов, страны, ASN.
- «По странам»: число адресов, организации, ASN.
- «По ASN»: число адресов, организации, страны.
- «Успешные запросы»: только записи `success=Yes`.
- «Сводка»: число адресов, процент успеха, уникальные значения без `N/A`, фактическое время сбора данных в UTC и длительность.

Успех означает, что API вернул хотя бы одно из полей: организация, страна, ASN или ISP. Это не гарантирует заполнение остальных полей. Отсутствующие значения обозначаются `N/A`. `request_status` содержит HTTP-статус или тип отказа; `error_type` — последнюю ошибку; `error_message` — историю ошибок попыток, включая ошибки основного источника при успешном резервном ответе. Внешние строки записываются безопасно как текст, а не формулы Excel.

Коды завершения: `0` — данные получены для всех адресов; `1` — ошибка файла или записи отчёта; `2` — отчёт записан, но есть неуспешные/пропущенные адреса. Ошибки аргументов также возвращают стандартный код argparse `2`, без создания отчёта.

## Ограничения и дальнейшее развитие

Адреса отправляются сторонним API. Обработка последовательная; при таймаутах и повторах она может занять значительно больше секунды на адрес. Отчёт записывается после завершения сбора, поэтому прерывание процесса не сохраняет промежуточные результаты. Версии зависимостей ограничены совместимыми диапазонами; это не lock-файл с точными версиями.

В следующих итерациях: кэширование, возобновление прерванных запусков, CSV/JSON-экспорт, настраиваемые источники, получение достоверных сетевых данных через RDAP и модульное разделение кода.
