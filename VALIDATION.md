# Проверка v1.2

Проверено 23 октября 2026 года на Python 3.12. Временные сценарии, входные файлы, отчёты и SQLite создавались вне Git. В репозиторий включены только рабочие модули и документация.

## Автоматические проверки

34 проверки прошли. Использовались временные каталоги и имитированные ответы HTTP для воспроизводимого испытания отказов:

- Старый отчёт сохраняется при ошибке формирования нового; запрет перезаписи работает и при конкурирующей записи.
- IPv4/IPv6, нормализация и порядок, дубликаты, неверные строки и служебные адреса.
- Резервный источник, таймауты, некорректный JSON, HTTP 429 и пауза источника для следующих адресов.
- Retry-After в секундах и HTTP-дате, включая ожидания свыше 60 секунд.
- RDAP: наиболее специфичный префикс IANA, проверка ответного диапазона, раздельные регистрационные/географические поля, HTTPS redirects и запрет HTTP downgrade.
- Полнота данных, происхождение полей и нормализация ASN разных провайдеров.
- SQLite TTL и контрольные точки; прерывание после первого адреса, продолжение только оставшихся и повтор из кэша без сетевых вызовов.
- JSON/CSV/XLSX, безопасная запись строк как текста, аудит отклонённых строк и корректные коды завершения.
- Сравнение значений и исчезновения данных; при прерывании незавершённые адреса не объявляются удалёнными.
- Повтор только ошибок, JSONL-журнал, защита входного файла от перезаписи через hard link.
- Bulk POST с несколькими адресами, ответ в другом порядке, отсутствующие/дублирующиеся элементы, резервный источник, группировка в несколько пакетов и ошибка ключа.
- Ключ bulk отсутствует в сериализованных результатах. Принудительный bulk без ключа завершается понятной ошибкой.
- Вывод без TTY ограничен тремя итоговыми строками; интерактивный прогресс переиспользует строку.

Компиляция всех пяти рабочих Python-модулей, `pip check` и `git diff --check` также прошли.

- Обработаны все шесть адресов исходного `ip_list.txt`: успешные геоданные и RDAP для 6/6.
- Выявлен реальный HTTP 303 от ARIN к другому реестру; после поддержки HTTPS redirects регистрационные поля получены корректно.
- Повтор с пятью результатами из кэша дозапросил один прежний RDAP-сбой и отметил появившиеся поля в сравнении.

Доступность API в будущем не гарантируется этим прогоном. HTTP 429 от основного источника обрабатывался через резервный API.

## Граница проверки bulk

Официальная документация IPWHOIS Pro подтверждает HTTPS POST `/bulk`, JSON-массив адресов и максимум 100 IP. Ключ `IPWHOIS_API_KEY` в текущей среде отсутствует: реальные платные запросы не выполнялись. Формирование запроса, обработка ответа и резервные сценарии проверены имитацией HTTP. Для реальной проверки нужен действующий платный ключ, заданный в переменных окружения.

Документация IPQuery описывала бесплатный bulk, но реальная проверка вернула `400: Bulk lookups are disabled due to abuse`. Этот источник не используется программой.

## Повторная ручная проверка

Запускайте из корня проекта, используя отдельный выходной каталог и не добавляя результаты в Git. Примеры ниже предполагают уже созданный каталог `outputs`:

```bash
.venv/bin/python main.py --input ip_list.txt --rdap --output outputs/baseline.json --log outputs/events.jsonl
.venv/bin/python main.py --input ip_list.txt --rdap --output outputs/cached.json --compare outputs/baseline.json
.venv/bin/python main.py --input ip_list.txt --rdap --resume --output outputs/resumed.xlsx
.venv/bin/python main.py --retry-failed outputs/baseline.json --output outputs/retry.json
```

Проверьте в сводке число HTTP-запросов и попаданий в кэш; в JSON — `field_sources`, `source_details`, `rdap_status`, `changes` и аудит входа. Если повторять нечего, `--retry-failed` завершается без нового отчёта. Для свежего сравнения используйте `--refresh`.
