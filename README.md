# whois_advanced v1.2

Консольный инструмент для анализа списков IPv4/IPv6: геолокационные API, регистрационные данные RDAP, кэширование, продолжение прерванных запусков и отчёты Excel/CSV/JSON.

## Установка и быстрый старт

Нужен Python 3.10+. Проверено на Python 3.12.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python main.py --input ip_list.txt
```

В Windows используйте `.venv\Scripts\python.exe`. Без `--input` программа читает `ip_list.txt` рядом со скриптом. По умолчанию создаётся Excel с UTC-меткой времени в имени рядом со скриптом. Явно заданные относительные пути отсчитываются от текущего каталога. Выходной каталог должен существовать.

Формат входного UTF-8-файла (BOM допустим):

```text
# По одному IPv4 или IPv6 на строку
8.8.8.8
1.1.1.1 # комментарий
2606:4700:4700::1111
```

Пустые строки и комментарии игнорируются. Дубликаты удаляются после нормализации адресов, порядок сохраняется. Ошибочные строки учитываются в аудите входа. Локальные, multicast и служебные адреса записываются как `skipped`, без внешнего запроса. Scoped IPv6 (`%interface`) не поддерживаются.

## Лаконичная консоль

В интерактивном терминале обновляется одна строка: прогресс, успешные ответы, кэш, продолженные адреса и приблизительное оставшееся время. После завершения выводятся три строки сводки с путём к отчёту. При перенаправлении вывода остаётся только сводка, без анимации и построчного вывода адресов.

- `--verbose`: подробный результат и диагностика каждого IP.
- `--quiet`: отключить прогресс и подробности, оставить итоговую сводку.
- `--log events.jsonl`: структурированный журнал старта, результатов и итогов; каждая строка — отдельный JSON. Ошибки попыток находятся внутри `record.events`.

Оценка времени приблизительна: скорость API, таймауты и попадания в кэш меняются в процессе запуска.

## Пакетные запросы

Поддержан официальный [Bulk endpoint IPWHOIS Pro](https://ipwhois.io/documentation/bulk): до 100 IPv4/IPv6 за HTTPS POST. Нужен платный тариф и переменная окружения `IPWHOIS_API_KEY`, заданная безопасно в настройках среды. Ключ не записывается в отчёты, SQLite или журнал. Не помещайте ключ в репозиторий или аргументы командной строки.

```bash
.venv/bin/python main.py --input ip_list.txt --batch on --batch-size 100
```

По умолчанию `--batch auto`: при наличии ключа используются пакеты, без ключа — бесплатные одиночные источники. `--batch on` требует ключ; `--batch off` отключает платный источник даже при заданном ключе. Из пакета заранее исключаются кэшированные, продолженные и непубличные адреса. Ответы сопоставляются по IP, а не по позиции в массиве. Для пропущенных или ошибочных элементов используются резервные одиночные API. Ключ не передаётся резервным источникам.

Пакет уменьшает число HTTP-запросов, но не обязательно стоимость: IPWHOIS Pro списывает кредит за каждый IP. RDAP не имеет общего bulk-протокола и запрашивается отдельно для адресов.

Бесплатный bulk не гарантируется: на момент проверки IPQuery описывал его в документации, но реальный endpoint отвечал `400` с сообщением об отключении bulk. Он не включён в рабочие источники.

## Источники и полнота данных

Без платного ключа программа последовательно пробует `ipapi.co`, затем `ipwhois.app`. Порядок можно изменить: `--providers ipwhois ipapi`. Первый содержательный ответ даёт географические поля. Названия организации и провайдера из геолокационных API не доказывают фактического владельца сервиса.

```bash
.venv/bin/python main.py --input ip_list.txt --rdap --output report.xlsx
```

С `--rdap` сервер выбирается по наиболее специфичному совпадению в официальных bootstrap-списках IANA. Проверяется, что ответный диапазон действительно содержит запрошенный адрес. Поддерживаются HTTPS-перенаправления реестров с ограничением числа переходов; переход на HTTP запрещён.

RDAP добавляет `netname`, `network_start`, `network_end`, `network_handle`, `registered_organization`, `registration_country`. Организация берётся из сущностей с ролью `registrant`; если реестр её не опубликовал, остаётся `N/A`. Регистрационная страна не заменяет географическую страну. `asn_description` остаётся `N/A`: описание ASN не выводится из имени сети.

`registered_organization` содержит опубликованное реестром имя регистранта; иногда это технический идентификатор, а не название юридического лица. ASN нормализуется к виду `AS12345`, чтобы ответы разных источников сравнивались одинаково.

У каждого результата есть `retrieved_at`, `source_url`, `field_sources` и `source_details` с источниками и временем получения. Кэш сохраняет исходные даты получения данных.

Полнота `completeness`:

| Значение | Значение для пользователя |
| --- | --- |
| `full` | Заполнены все восемь географических полей; при `--rdap` также все шесть регистрационных |
| `partial` | Получены данные, но часть ожидаемых полей отсутствует |
| `failed` | Содержательных данных не получено |
| `skipped` | Непубличный/служебный адрес, внешние запросы не выполнялись |

`success=Yes` означает наличие данных, а не гарантированную полноту. Причины пропусков полей перечислены в `missing_fields`. Сбой RDAP не уничтожает успешные геоданные, но отражается в `rdap_status`, итоговой сводке и коде завершения.

## Кэш и возобновление

```bash
# Продолжить прерванный запуск
.venv/bin/python main.py --input ip_list.txt --rdap --resume

# Получить свежие данные, обновив кэш
.venv/bin/python main.py --input ip_list.txt --rdap --refresh

# Отключить чтение и запись кэша
.venv/bin/python main.py --input ip_list.txt --no-cache
```

По умолчанию `.whois/state.sqlite3` рядом со скриптом хранит кэш и контрольные точки. `--state-dir /path/to/state` меняет каталог. Результат каждого адреса фиксируется отдельной транзакцией. При Ctrl+C программа пытается сохранить частичный отчёт и завершиться с кодом `130`; уже зафиксированные адреса доступны даже после аварийной остановки.

`--resume` использует тот же нормализованный упорядоченный список, набор источников, bulk-режим и настройку RDAP. Успешные и намеренно пропущенные адреса переиспользуются; ошибки повторяются. Срок кэша не ограничивает явное возобновление. Время запроса/задержку можно изменить. `--resume` и `--refresh` несовместимы.

Обычный кэш живёт сутки (`--cache-ttl 86400`, секунды), переиспользуется между разными входными файлами с одинаковыми настройками источников и хранит только успешные результаты; при включённом RDAP требуется также успешный RDAP. `--cache-ttl 0` отключает чтение свежести, но позволяет обновлять записи. `--no-cache` не отключает контрольные точки для `--resume`.

SQLite содержит обработанные IP и результаты: храните служебный каталог с теми же правами доступа, что и отчёты. Старые контрольные точки автоматически не удаляются. `.whois`, локальные отчёты с обычным префиксом и журналы исключены из Git.

## Форматы и сравнение

```bash
.venv/bin/python main.py --input ip_list.txt --output baseline.json
.venv/bin/python main.py --input ip_list.txt --refresh --compare baseline.json --output changes.xlsx
.venv/bin/python main.py --input ip_list.txt --output report.csv
.venv/bin/python main.py --input ip_list.txt --output report.json --log events.jsonl
```

- Excel: семь листов — все адреса, три группировки, успешные запросы, сводка и ошибки входа. При сравнении добавляется восьмой лист «Изменения». Пустые листы сохраняются.
- JSON: версия схемы, сводка, типизированные записи, ошибки входа и изменения. Рекомендуется для автоматизации и полного сохранения метаданных.
- CSV: таблица записей с UTF-8 BOM; вложенные значения записываются JSON-строками. Для аудита входа и сводки добавьте `--log`. Сравнение при CSV требует `--log`, куда попадают подробные изменения.

`--compare` читает JSON/CSV/XLSX, в том числе отчёты v1.1. Сравниваются географические и регистрационные поля; фиксируются добавленные/удалённые адреса, изменённые значения, появившиеся и исчезнувшие данные. Исчезновение данных отделено от изменения значения и не означает смену владельца. Необработанные из-за прерывания адреса не объявляются удалёнными. Сравнение по умолчанию может использовать кэш; для свежего сетевого сравнения укажите `--refresh`.

```bash
# Повторить только неуспешные записи из прежнего отчёта
.venv/bin/python main.py --retry-failed report.json --output retry.json
```

`--retry-failed` принимает JSON/CSV/XLSX, исключает `skipped`, обходит чтение обычного кэша и создаёт отдельный отчёт повторной попытки. Для ошибок RDAP он автоматически включает RDAP. Частичные, но успешные результаты без ошибки RDAP не считаются неуспешными. Исходный отчёт не изменяется. При сочетании с `--resume` могут быть переиспользованы успешные контрольные точки предыдущей попытки.

Все отчёты записываются через временный файл в том же каталоге и заменяются только после успешного сохранения. Без `--overwrite` существующий файл не заменяется даже при конкурирующей записи. С `--overwrite` прежний отчёт сохраняется, если формирование нового завершится ошибкой. Для этого требуется файловая система с поддержкой hard link при записи без перезаписи. Служебные временные файлы удаляются автоматически. Поля из внешних источников в Excel/CSV защищены от интерпретации как формулы. Строки Excel ограничиваются размером ячейки; полные значения сохраняются в JSON.

## Остальные параметры

```bash
.venv/bin/python main.py --help
.venv/bin/python main.py --version
```

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `--format` | по расширению или `xlsx` | `xlsx`, `csv`, `json`; расширение должно совпадать |
| `--timeout` | `10` | Таймаут соединения/чтения, не общий лимит запуска |
| `--delay` | `1` | Пауза между одиночными адресами/пакетами |
| `--retries` | `2` | Повторы после первой попытки при временных сетевых ошибках и HTTP 500/502/503/504 |
| `--batch-size` | `100` | Число адресов в группе, от 1 до 100 |
| `--overwrite` | выключен | Разрешить замену отчёта и явно заданного журнала |

После `429` источник ставится на общую паузу, обработка продолжается через резерв. `Retry-After` поддерживает секунды и HTTP-дату; указанное сервером ожидание не сокращается. При `503` с этим заголовком тоже используется пауза. После исчерпания временных ошибок источник ставится на паузу на 30 секунд, после `401/403` — на 300 секунд. Проверка TLS остаётся включённой. Ключ bulk не передаётся при перенаправлениях.

Коды завершения: `0` — запуск завершён без отклонённых/неуспешных/пропущенных адресов и ошибок RDAP; `1` — ошибка файла, хранилища или конфигурации; `2` — отчёт записан, но есть проблемы входа или обработки; `130` — прерывание пользователем. Ошибки аргументов argparse также возвращают `2`, без отчёта. `partial` без технической ошибки допустим при коде `0`.

## Доступ к сети и структура

Бесплатные API: `ipapi.co`, `ipwhois.app`. Bulk: `ipwhois.pro`. RDAP: `data.iana.org`, затем выбранный реестр; обычно `rdap.arin.net`, `rdap.db.ripe.net`, `rdap.apnic.net`, `rdap.lacnic.net`, `rdap.afrinic.net`. В ограниченной среде эти HTTPS-домены должны быть разрешены. IP передаются выбранным сторонним источникам. Доступность и тарифные лимиты определяются провайдерами.

Рабочие модули: `main.py` — CLI и сценарий запуска; `providers.py` — источники и RDAP; `storage.py` — атомарная запись и SQLite; `reporting.py` — экспорт и сравнение; `console.py` — прогресс. Зависимости ограничены диапазонами в `requirements.txt`; это не точный lock-файл.
